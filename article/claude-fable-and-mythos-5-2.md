# Claude Fable 5.2와 Mythos 5.2 발표 정리

{% hint style="info" %}
이 글([https://www.anthropic.com/claude-fable-and-mythos-5-2](https://www.anthropic.com/claude-fable-and-mythos-5-2))은 Anthropic이 2026년 11월 9일에 발표한 Claude Fable 5.2와 Mythos 5.2 소개 글을 읽고, 핵심 내용과 개발자가 알아 둘 점을 간단하게 정리한 글이에요.

원문을 그대로 옮긴 번역은 아니에요. 수치는 원문 기준이고, API 관련 내용은 개발자 문서 [What's new in Claude Fable 5.2](https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2)를 함께 참고했어요.
{% endhint %}

### Introduce

Anthropic이 Fable과 Mythos의 새 버전인 5.2를 발표했어요. 두 모델은 사실 같은 기반 모델이고, 사이버 보안과 생물학 분야의 세이프가드를 어떻게 걸었는지, 그리고 누가 쓸 수 있는지만 달라요.

가장 눈에 띄는 건 가격이에요. 대부분의 벤치마크에서 Fable 5.1보다 크게 앞서는데, 가격은 100만 토큰당 입력 $10 → $8, 출력 $50 → $40으로 오히려 20% 내려갔어요. 출력 생성 속도도 최대 30% 빨라졌다고 해요.

### 한눈에 보기

| 항목            | 내용                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------- |
| 발표일           | 2026년 11월 9일                                                                             |
| 모델 ID         | `claude-fable-5-2`, `claude-mythos-5-2`                                                  |
| 가격 (100만 토큰당) | 입력 $8, 출력 $40 (Fable 5.1은 $10 / $50)                                                     |
| 컨텍스트 / 최대 출력  | 1M 토큰 / 128K 토큰                                                                          |
| 속도            | 출력 생성이 Fable 5.1·Mythos 5.1보다 최대 30% 빠름                                                  |
| 패스트 모드        | 입력 $16, 출력 $80. 토큰 생성 속도 최대 2.5배                                                         |
| 제공 플랫폼        | Claude API, AWS(Amazon Bedrock, Claude Platform on AWS), Google Cloud, Microsoft Foundry |

***

### 1. Fable과 Mythos는 무엇이 다를까

두 모델의 성능은 같아요. 차이는 세이프가드와 사용할 수 있는 사람이에요.

| 구분    | Fable 5.2               | Mythos 5.2                                                        |
| ----- | ----------------------- | ----------------------------------------------------------------- |
| 세이프가드 | 사이버 보안·생물학 분야에 강한 보안 적용 | Fable 같은 분류기 차단 없이 이중 용도(dual-use) 작업까지 가능                        |
| 사용 대상 | 모든 사용자                  | 검증 프로그램을 통과한 조직만                                                  |
| 접근 방법 | API와 클라우드 플랫폼에서 바로 사용   | Cyber Verification Program, Life Sciences Verification Program 신청 |

Fable은 침투 테스트, 익스플로잇 작성, 바이너리 기반 취약점 분석 같은 고위험 사이버 작업과 대부분의 생물학 연구 작업을 분류기로 막아요. 막힌 요청은 사이버 쪽은 Opus 4.8이, 생물학 쪽은 Opus 5가 대신 답해요. 그리고 Claude Enterprise 고객은 검증 프로그램에 들어가지 않아도 Mythos 5.2 기반의 Claude Security를 쓸 수 있다고 해요.

***

원문의 비교 표에서 Claude 모델끼리만 추려 보았어요. 다른 회사 모델과의 비교는 원문에서 확인할 수 있어요.

| FrontierSWE v2 (에이전트 코딩)            | 69.9%         | 56.3%         | 62.3%    |
| AutomationBench (업무 자동화)            | 51.4%         | 31.4%         | 42.5%    |
| Terminal-Bench-Science 0.1 (과학 연구)  | 74.6%         | 52.6%         | 58.7%    |
| WANDR (에이전트 검색)                     | 82.1%         | 68.7%         | 72.3%    |
| OSWorld 2.1 (컴퓨터 사용)                | 89.3%         | 83.5%         | 87.2%    |
| RoboDojo Sim (로보틱스)                 | 64.9%         | 27.6%         | 39.4%    |

사이버 보안은 Mythos끼리 비교했고, Opus 5.5는 세이프가드를 끈 상태의 점수예요.

점수만큼 비용 대비 성능도 볼 만해요. FrontierCode 2.0에서 Fable 5.2는 `high` effort만으로 45.3%를 기록해 Opus 5.5의 최고 점수(45.5%)와 비슷했는데, 작업당 비용은 절반 정도였어요. Humanity's Last Exam에서는 `low` effort로 Opus 5.5 최고 점수와 같은 수준을 작업당 비용 10분의 1 이하로 냈다고 해요.

### 3. 실제 사례

#### 코딩

* **운영체제 프로토타입:** 빈 폴더에서 시작해 8일 동안 쉬지 않고, Fable 5.2가 1,000개가 넘는 서브에이전트를 조율해 코드를 작성·테스트·리뷰. 결과물은 노트북에서 부팅되고, 기기를 구동하는 자체 코어, 디스크·키보드·네트워크 드라이버, 파일 저장, 창, 로그인 화면, 설치 프로그램, Claude 기능까지 포함.
* **Python → Rust 이전:** 개발 중이던 Fable 5.2 버전으로 에이전트 팀이 핵심 프로덕션 서비스를 Rust로 이전. 더 효율적이고 안정적이 됐고, 시작 시간은 약 26배 빨라짐.

#### 과학·공학

| 분야     | 내용                                                                                                                                                                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이론 물리  | 홀로그래피 이중성(holographic duality)을 이용해 블랙홀 관련 미해결 문제 2개를 풂. 2003년에 계산이 너무 방대해 끝내지 못했던 작은 우주에서의 계산을 거의 자율적으로 완료해, 작은 우주에서도 블랙홀이 갑작스럽게 형성된다는 걸 확인. 15년 넘게 양자중력 후보 이론을 걸러 내는 데 쓰인 기법의 정확한 한계도 찾음. |
| 단백질 구조 | Mythos 5.2가 오픈소스 단백질 폴딩 모델 2개를 조합해 AAV 캡시드 전체 구조를 예측. 시도한 34개 중 28개를 정확하게 모델링.                                                                                                              |
| 수학     | Fable 5.2 에이전트 약 1,000개가 페르마의 마지막 정리를 Lean으로 30시간 만에 완전히 형식화. 첫 시도(미공개 연구 버전, 11일)보다 액션 토큰은 3분의 1, 증명 길이는 7분의 1. 같은 설정의 Opus 5.5는 18시간에 26%를 완료한 뒤 30시간까지 거의 진전이 없었음.                       |
| 하드웨어   | 한 문단짜리 프롬프트로 음성 비서 허브, USB 스피커폰, 휴대용 가상 펫 3종을 설계. 4층 회로 기판, 3D 프린팅 케이스, 소프트웨어까지 만들었고, 전기적 수정 없이 모두 동작.                                                                                      |
| 로보틱스   | RoboDojo Sim에서 64.9%(Opus 5.5는 39.4%). 퍼즐 큐브 맞추기, 병뚜껑 열기, 로봇 그림 그리기 같은 작업을 시연.                                                                                                              |

### 4. 안전성

성능만큼 안전성 평가도 꽤 자세히 공개했어요.

* **정렬 감사:** 약 1,900개 시나리오의 자동 행동 감사에서 Mythos 5.2의 정렬되지 않은 행동(misaligned behavior) 점수는 2.67(낮을수록 좋음). Opus 5.5 2.79, Sonnet 5.5 3.10, Mythos 5.1 3.28.
* **샌드박스 탈출:** 일부러 약점을 둔 1,800여 개 시나리오에서 샌드박스 밖의 자격 증명이나 파일을 쓴 비율은 Mythos 5.2가 3.1%. Opus 5.5 3.3%, Sonnet 5.5 5.1%, Mythos 5.1 21%, Mythos 5 39%.
* **과잉 차단 감소:** Fable 5.2의 세이프가드 차단은 Fable 5.1보다 약 55% 줄었음(사이버 약 60%, 생물학 약 40%). claude.ai, Claude Code, Cowork 초기 테스트 기준.
* **증류 방지:** 지금까지 공개한 모델 중 가장 강한 증류(distillation) 방지를 적용해, 증류 목적의 데이터 수집을 90\~99% 줄였다고 함. 이전 컨텍스트를 고쳐 추론을 빼내는 걸 막는 preserved thinking도 이제 모든 계정에 적용.
* **AI R\&D 능력 제한:** 가속기 커널 최적화와 LLM 아키텍처 개선 능력은 학습 단계에서 Opus 5.5 수준으로 제한. 관련 주제 일부는 Opus 5가 대신 답함. 에이전트 코딩, 하드웨어 개발, 일반적인 AI/ML 연구는 영향 없음.

다만 좋은 결과만 있는 건 아니에요. Mythos 5.2는 한 가지 유해 행동 지표에서 Opus 5.5보다 약간 나빴고, Mythos 5.1과는 비슷한 수준이었어요. 또 두 모델 모두 최근 모델들보다 "지금 평가받고 있다"는 의심을 더 자주 드러냈다고 해요. 자세한 내용은 시스템 카드에 있어요.

### 5. 개발자가 알아 둘 점

개발자 문서에서는 대부분의 작업은 최신 Opus 모델로 시작하고, Opus를 높은 effort로 써도 부족할 때 Fable 5.2로 옮기라고 권해요. 옮길 때는 모델 ID만 바꾸면 되지만, Fable 5.1에서 아래 네 가지는 코드가 깨질 수 있어요.

```python
model = "claude-fable-5-1"  # Before
model = "claude-fable-5-2"  # After
```

| 변경             | 내용                                                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 이전 대화를 고치면 400 | `system`, `tools`, 이전 메시지를 바꾼 뒤 thinking 블록을 다시 보내면 400 오류. Fable 5.1은 2026-08-31 이후에 만든 계정만 해당했지만, 5.2는 모든 계정에 적용. 대화 기록은 덧붙이기(append-only)만 해야 함. |
| thinking 블록 호환 | Fable 5.2의 thinking 블록은 Fable 5.2와 Mythos 5.2만 읽음. 다른 모델로 넘기면 그 턴의 추론은 버려짐(오류 없이 빠지고 과금도 없음).                                                       |
| 컴퓨터 사용         | `computer_20251124`는 Amazon Bedrock을 빼고 모두 400 오류. `computer_toolset_20260801`로 바꿔야 함.                                                              |
| advisor 도구     | Fable 5.2가 실행 모델(executor)이면 advisor는 `claude-fable-5-2`나 `claude-mythos-5-2`만 가능.                                                                  |

첫 번째 항목은 요청을 직접 조립하는 코드에만 해당해요. Claude Code, claude.ai, Claude Managed Agents, Claude Agent SDK를 쓰고 있다면 달라지는 게 없어요.

그 밖에 알아 두면 좋은 점도 정리해 보았어요.

* thinking은 항상 켜져 있어요. `{"type": "disabled"}`나 `budget_tokens`를 보내면 400이 나고, 생각하는 깊이는 effort로 조절해요.
* effort 기본값은 `high`예요. 성능 향상의 대부분이 이미 `high`에서 나온다고 해서, `xhigh`는 측정으로 이득이 확인된 어렵고 긴 작업에만 쓰라고 권해요.
* 프롬프트에 "고민하지 말고 바로 답해"라고 써도 `medium` 이상에서는 생각을 해요. 쉬운 요청이 느리거나 비싸다면 effort를 낮춰야 해요.
* `tool_choice`로 `any`나 특정 도구를 강제하면 400이에요. `auto`에 `strict: true`를 쓰거나 JSON 출력을 쓰면 돼요.
* 30일 데이터 보관이 필요해서, 별도 승인 없이는 ZDR(zero data retention) 환경에서 쓸 수 없어요.
* 배치 처리는 100만 토큰당 입력 $4, 출력 $20이에요.

### Summary

> Fable 5.2는 Fable 5.1보다 대부분의 벤치마크에서 크게 앞서면서도 가격은 20% 내려간 모델이에요.\
> API로 쓴다면 대화 기록을 덧붙이기만 하는지(append-only)부터 확인하고, effort는 `high`에서 시작하면 돼요.
